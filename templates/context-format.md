# Context format (`.ambicode/context/`)

Learning context for agents: small, deduplicated, fixed-shape files so an agent reads only the one it needs.
Limits come from `context.maxFileTokens`, `context.maxIndexTokens` (`index.md` only) and `context.maxTotalTokens` in `.ambicode/config.yaml` (defaults 2500, 5000 and 60000; tokens = chars / 4).

## Kinds (the only paths `context write` accepts)
- `overview.md`: purpose, stack, layout of the repository, one screen.
- `navigation.md`: how to find things.
- `conventions.md`: how code is written here, as facts. A convention that became a rule (`.ambicode/policies/`) is not repeated here.
- `modules/<directory>.md` or `modules/<directory>/overview.md`: exactly one per module, at the note path `ambicode context tree` prints. A leaf module is its directory path relative to the repository root with `.md` appended (`src/app/features/dashboard` -> `modules/src/app/features/dashboard.md`); a module with submodules keeps its note inside its folder (`src/app/features` -> `modules/src/app/features/overview.md`). Segments are letters, digits, `.`, `_`, `-`; no `..`. A module is a directory, at any depth under a source root, that holds source files itself or branches into two such directories. `ambicode context tree` lists them with their note paths. No other files.
- `index.md`: the grep target for ticket words, one file, see below.

## Per-file structure
- H1 = the file's purpose, one line, unique across all files. Exactly one H1.
- H2 sections fixed per kind, in this order, each heading at most once per file. Keep an empty section's heading, omit its bullets.
  - `overview.md`: `## Purpose` (1-2 bullets), `## Projects` (`- <id> - <path> - <what it is>`), `## Stack` (`- <tool>: <role>`).
  - `navigation.md`: `## How to read` (one bullet: list, open one file, Grep the name, Read with offset/limit; never Read whole large files), `## Entry points` (`- <path> - <role>`), `## Where things live` (`- <thing>: <path or glob>`), `## Naming`, `## Grep patterns` (`- <what>: <pattern>`).
  - `conventions.md`: `## Code`, `## Errors`, `## Tests`, `## Imports`; one convention per bullet.
  - module notes: `Root: <module dir from the repo root>` directly under the H1 (generated by `context write`; never write it; every other path in the note is relative to it), `## Purpose` (2 bullets: what the folder is for, then what roles it contains), `## Key files` (filled by `context write` from the code: `- <path relative to Root> - <Name>, <Name>, ...` per source file of the module itself, files with the most exported declarations first, within the file limit; do not write it, only a bullet that repeats a generated path as `- <path> - <name>(args): <what it does>` is kept), `## Folders` (filled by `context write`; write only the empty heading: the folders below the module that hold source files but are not modules, one bullet each, `- <dir relative to Root>/ - <base name>, <base name>, ...`, so every source folder is named in some note; a bullet repeated as `- <dir>/ - <base name>, ...: <what the folder holds>` is kept), `## Submodules` (`- <child note path relative to this note's directory> - <what that folder holds>`, e.g. from `modules/a/b/overview.md` the child `modules/a/b/c.md` is `c.md` and `modules/a/b/c/overview.md` is `c/overview.md`; `context write` rewrites a full `modules/...` path to this form and reports `submodule-link` for one that names no note; only for a module that has child modules), `## Depends on`, `## Gotchas`.
- `index.md`: H1, then the folder tree of the modules, nothing else. One line per module folder, indented two spaces per tree level (roots are level 1), as a link to that folder's note: `- [<dir>](<note path>)`, where the link text is the folder path relative to the folder line above it (a root folder keeps its full path) and the link target is always the full note path; the full folder path is the target without the leading `modules/` and the trailing `/overview.md` or `.md`. Each line may end with ` - <description>`: the first `## Purpose` bullet of that folder's note, cut at 12 words, and then ` | <Name>, <Name>, ...`: the names of that note's `## Key files` bullets without their paths, deduplicated, the first 8 then `+N` (both generated from the notes on disk; a folder whose note is missing or lacks the section has no such part; names without a description give `- [<dir>](<note path>) | <names>`). A child folder's line follows its parent's line. There are no file lines: files and entities are in the notes' `## Key files` and `## Folders`. Every link must name a note of the bundle or already written. Folders are listed level by level, parents before children, shallowest first, up to the last whole level that fits the budget; deeper folders are reached through the parent note's `## Submodules` links. No other lines: no aliases, no categories, no invented names. It has its own budget, `context.maxIndexTokens` (default 5000, not `maxFileTokens`) and counts toward `maxTotalTokens`. Its purpose is to define the hierarchy and boundaries of the project's functionality (which folder holds which files and entities, where one folder ends and the next begins), so a later agent can map a ticket to the right scope. `ambicode context tree --level <n>` prints a level with its file lines for the scout; those lines are not index.md lines. Example:

  ```
  # Index
  - [src/billing](modules/src/billing/overview.md) - Invoices, tax and payment export | Invoice, InvoiceLine, totalOf, taxFor
    - [export](modules/src/billing/export.md) - CSV and PDF export of invoices | writeCsv, renderPdf
  - [src/auth](modules/src/auth.md) - Sign-in and session handling | Session, startSession
  ```
- Bullets sorted by path or name. Same repo state gives the same file.
- No hedging ("probably", "seems"), no dates, no drifting counts.
- No code bodies: code fences are refused; a signature is one line inside a bullet. Paths over prose.
- One fact in one file; point to another by relative path.

## Bundle format for `context write`
One call, bundle on stdin; each file starts with a line `=== <path relative to .ambicode/context/>`:

```
=== overview.md
# Overview of <repo>
## Purpose
- ...
=== modules/<note path from context tree>
# <directory> module
...
```

- `ambicode context write --replace` removes context files not in the bundle; without `--replace` only the named files change. `--root <dir>` (repeatable, the roots of `context tree`) tells it which module tree decides which module a file belongs to.
- Output is JSON `{written, removed, check: {problems}}`. Exit 1 and nothing written when `problems` is not empty (file too large, total too large, bad index.md line or indentation, index link to a missing note, duplicate H2 in a file, duplicate H1 across files, code fence, path outside the kinds). Fix with one more call naming only the changed files.
- `ambicode context list` prints path, H1 and approximate tokens per file, indented by folder; notes more than two levels down are counted on their level-1 parent.
- `ambicode context tree [--root <dir>...]` prints the modules of the source roots at full depth (note path, directory, depth, file count, submodules); it writes nothing.
- `ambicode context tree --root <dir> --index` prints the index.md body described above, built from the notes already written.
- `ambicode context tree --root <dir> --level <n>` prints one level of that tree in the index.md shape: each folder of the level (roots are level 1) as a linked line, then one line per unique file base name with the names its files declare. Companions (tests, stories, mocks, styles, templates) are left out. Names beyond 8 per base name are counted as `+N`.
