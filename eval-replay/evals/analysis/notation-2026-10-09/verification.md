## Findings

### P1 — An unfinished assistant draft is accepted as a final answer

Responsible code: [trace-analysis.mjs](../../../../evals/scripts/src/analysis/trace-analysis.mjs), lines 68–86; [bench-score.mjs](../../../../evals/scripts/src/analysis/bench-score.mjs), lines 255–258.

`parseTrace` retains text from any assistant message, including one that also requests tools, then assigns `finalText ??= lastText` when no terminal result is present. Scoring accepts this string without any finality check. A missing paid grader therefore turns a provisional answer into a completed scored answer.

Two isolated reproductions have an assistant message listing both true files **and an outstanding Read tool call**, with no result event or final completion. One run has a maximum-turns error, the other a truncated trace with no error. Both currently produce:

```json
{"absent":false,"recall":1,"precision":1,"answerFromTrace":true}
```

This can bias recall and absent-share checks toward passing. A run reaching its limit can remain an arm outcome without treating intermediate commentary as its finished answer. The new `e-last` test currently blesses an assistant-only transcript as completed; it does not cover pending tools or completion provenance.

Required change: recover only an independently established final answer, such as a terminal successful result or a validated completed-answer artifact. If supporting traces without a result event, explicitly establish finality and rule out outstanding tool calls/interrupted drafts. Keep trusted grader evidence behavior separate, preserving existing treatment of graded limit outcomes. Add negative tests for the two reproductions and result-error cases. All four real recovered answers have terminal final text, so this restriction can retain their recovery.

### P2 — Recovered answers still disappear from report diagnostics

Responsible code: [run-report.mjs](../../../../evals/scripts/src/analysis/run-report.mjs), lines 208–210 and the later `row.step && row.namedFiles` map-diagnostic branch.

The scorer uses trace text, but `analyzeResult` still obtains `row.answer` exclusively from grader evidence. On the actual four recovered attempts, it now reports correct recall with:

```text
answer: null
namedFiles: null
map diagnostics: absent
```

Reproduced IDs: `e-iq5BqM`, `e-3oNv5m`, `e-7evXFs`, `e-Bj9KZ3`. Their numeric scores are recovered, but named-answer files, map omissions, and outside-map findings remain excluded. This repeats the flattering-subset problem in diagnostics rather than in the main mean.

Required change: carry the scorer's selected answer and its provenance to reporting, and use the same extraction contract for both scores and diagnostics. Add an end-to-end report fixture asserting `answer`, `namedFiles`, and map diagnostics for a completed skipped-grader answer. Do not introduce another independent final-answer extractor.

The `grader-skipped` caveat also assumes every trace fallback means the paid grader was skipped, while fallback occurs whenever evidence is missing. Use the actual `skippedPaidGraders` flag for that explanation; otherwise label the source as trace recovery without asserting a cause.
