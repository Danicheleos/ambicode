**What broke.** Six plugin runs stopped mid-route, across plan, review and task. In every one, the
AMBICODE guard (`scripts/guard.mjs`, PreToolUse) blocked or asked about a write. A headless run
cannot answer an ask, so the model stops the route. Three causes:

- **G1. Wrong deny message for the plan body.** This is a plugin bug and broke 2 runs.
  - The model wrote `mkdir -p .ambicode/tasks/<slug>/steps && cat > …/steps/plan-body.md`.
  - The guard checks the `mkdir` target first. It is under `.ambicode/tasks/` but is not the plan
    body, so the guard answers with the note-save message.
  - The model followed it, saved through `note save`, and the route never saw the plan.
  - The plan-body message ("Write it with the Write tool") was never shown.
- **G2. `cd` and then a relative path makes the guard ask.** This broke 3 runs.
  - The guard records only *that* a `cd` happened, not where to, so `cd repo && cat >> tests/x`
    becomes "cannot tell where this writes".
  - Every fixture lives in `repo/`, and the models routinely `cd repo`.
  - One of the 3 runs (plan-accept 1) also hit **G2b**, a parser bug. In BSD
    `sed -i '' 's#a#b#g' file`, the guard reads `''` as the script and the script as the file.
- **G3. A write to `$TMPDIR/shim.js`** broke 1 run. The guard cannot know the path, so asking is
  correct. The model chose to build a test shim, which is behaviour, not a guard defect.

**Plan quality** did not improve with the stricter Tests line. `plan-quality` passed in 1 of the 3
completed plan-accept runs.

**Cost:** $7.64 for model runs, $5.62 plugin and $2.02 bare.

## 3. Fix options (not applied)

All are plugin fixes that edit the existing guard code. No eval changes.

- **G1.** When any target in the command is the plan body, use the plan-body message for every
  `.ambicode/tasks/<slug>/steps/` target in that command. Alternatively, don't count a `mkdir` of
  the task's own `steps/` directory as a write the guard denies. The first is the smaller edit,
  because it changes which reason is chosen and nothing else.
  - Test: the plan-accept-3 command gets a deny with "Write it with the Write tool".
- **G2.** Replace `moved` with the current directory: a literal `cd <dir>` updates it through the
  existing `normalize(dir, cwd)`, and later relative targets resolve against it. Only an opaque
  `cd` target (`cd $X`, `cd -`, `popd`) keeps today's ask.
  - Test: `cd repo && cat >> tests/page.test.js` gives no ask, and `cd $D && cat > x` still asks.
- **G2b.** In the `sed` branch, a bare `-i` followed by an empty word takes that word as the
  suffix.
  - Test: `sed -i '' 's#a#b#g' file` writes only `file`.
- **Plan citations.** Give `routes/plan/write.md` the same wording as investigate's read.md: the
  full repository-relative path, never a bare file name.
- **G3.** No change: an opaque write should ask.
