## 4. Options reported, not implemented

- **Investigate duplicate output (about 2.5 KB, 700 tokens, about 4 s per run, 1 of 3 calls).** Cleanest fix: drop the stdin note and have the Stop hook save `last_assistant_message` as the investigation note, then run `check-citations` there. It changes the order of ledger steps (`read` produces `note{investigation}` before the final message; `check-citations` has `onFail: revise read`), so it is more than a small edit. Rejected here: the cases' prompts demand the answer in the final message, so a short final message would lose recall points.
- **Plan final message restates the plan (1.7-1.9 KB).** The gate prints `note{plan-draft}` to the model, not necessarily to the user; telling the model to skip the restatement could leave the user without the plan. Needs a decision on who shows the draft.
- **`review record` input (2.1-2.8 KB per review run, about 700 tokens, 3-4 s).** The reviewer's JSON passes through the main model. Option: a `SubagentStop` hook that writes the subagent's last message to the task dir and a `review record` with no stdin that reads it. `hooks/hooks.json` has no `SubagentStop` entry, so it needs a new hook event handler, a guard change and tests: not small, not done. It also removes the "do not edit its findings" risk.
- **`route next` round trips.** In `execute.ts` `execute()` already chains code steps after a model step inside one call, so a pure handshake exists only after a gate or a Write. The plan `route next` after the Write (127-131 B result) could be a PostToolUse hook on `Write(.ambicode/tasks/*/steps/plan-body.md)` that advances the route; that adds a hook entry and a second trigger path to the ledger. Not done. The review-run `route next` after the estimate gate returns the next step, so it is not pure.
- **A citation revise re-prints the whole read step (about 1.1 KB, trace investigate-trace-1).** The code revise already sends "Inputs unchanged" for payloads; the instruction text could be omitted the same way. About 300 tokens on 20% of investigate runs. Not done.

## 5. Considered and rejected

- Dropping `none recorded` lines (Revisions, Navigation, Requirements) from Evidence: saves about 150 B but an absent result would read as clean. CLAUDE.md forbids that.
- Shortening the 58-character review id in Evidence and Not verified: saves about 100 B per task run but loses the pointer to `.ambicode/reviews/<id>`.
- Collapsing repeated `green-unproven limit (1) at change` lines with `xN`: `engine.ts:85` counts these lines for the closing message and the status counts raw items, so the numbers would disagree.
- Deleting the plan SKILL.md Boundary section: tests assert each prohibition and the guard does not enforce "do not run project scripts" in plan.
- Removing the `prompts/shared-operating-contract.md` and `prompts/reviewer-role.md` dead files: part of the Phase 2 list but a test (`skill-content.test.ts`, "canonical shared operating contract") reads the first; left for the same pass as the rules change.
- Shortening `prompts/session-contract.md` (952 B): its Route section is what the Stop and step flow rely on, and I have no trace evidence that any line is unread.
