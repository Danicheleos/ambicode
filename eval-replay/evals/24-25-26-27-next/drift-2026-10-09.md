# Per-case drift audit — 2026-10-09

**The ±10% target is not met.** Among the 19 investigation cases with three repetitions, 11/19 stay within 10% of their best recall, 4/19 for precision, 8/19 for F1, 3/19 for agent cost, 1/19 for harness turns and 5/19 for peak context. No case keeps all three API-call counts within the band; no case keeps harness wall time within it. All 19 have stable initial context within the band.

The engine serves identical starting prompt/contract/normalized step/map within every main investigation case. The first observable model-request divergence is tool 1 in most pairs (tool 2 for FE438 R1/R2). The largest quality losses occur later in selecting UI/translation families and deciding which evidence files belong in the final change inventory. Stable engine inputs do not create stable model decisions.

This report covers **88 attempts in 30 case/campaign groups**: 58 investigation answers from runs 15/16 (19 complete three-run cases plus one FE5967 attempt), 24 skill-walk attempts from run 17, and six task attempts from runs 18/19. The later build is kept separate. Every case has a complete metric grid with its own reference per metric, pairwise first-request differences, exact final path-set deltas, and linked step-by-step I/O for each attempt.

## Corrected cost accounting

An error in my earlier report is corrected here. In **all 88 attempts**, raw harness `costUsd` equals terminal trace `total_cost_usd` plus `judgeCostUsd` (maximum floating-point residual 5.2e-17). The agent-only value is the terminal trace cost. Judging was already included in the reported total, not an additional cost on top. [evals/scripts/src/validation/eval-gate.mjs](../../../evals/scripts/src/validation/eval-gate.mjs) at lines 96–99 currently compares raw totals while describing them as agent-only. All new tables separate agent, judge and total.

This can change the winning repetition: FE6404 R1 is the cheapest agent attempt ($0.1394474), R2 is $0.1396888, R3 $0.1453528. Judge-inclusive totals can suggest a different ranking. On the matched 19-case previous/latest full-cohort comparison, the corrected approximate agent ratio to the cached bare arm is 1.186×, so the earlier cost failure remains a failure; only its accounting label and value change. This is an offline correction using recorded costs, not a new bare run.

## How the target is defined

For each case, choose independent witnessed optima: maximum recall, precision and F1; minimum agent cost, wall time, turns, API requests and context. Quality must be ≥0.9× its maximum; resources ≤1.1× their minimum. A best recall of 0.50 therefore requires ≥0.45, not ≥0.40. No zero-cost/zero-error division is invented. Counts are discrete: six calls permit at most 6.6, hence six actual calls. One additional call already breaks this narrow band.

The best-F1 attempt is a balanced quality witness, not a replacement for separate metric winners. A second table in every case shows resources among attempts that simultaneously meet 90% of best recall, precision and F1 and have a completed engine route. A fast low-quality or blocked attempt cannot demonstrate a good workflow. FE6141 has **no observed repetition** meeting all three quality floors at once; a hypothetical composite of R3 recall and R1 precision must not be reported as achieved. Stable zero recall in a blocked task/replayed review is failure, even when the numerical spread is zero.

Three observations do not establish a future variance bound or causal effect. The best observed run is a selection-biased aspiration, not an estimate of expected performance. Results here describe this sample, without claiming a confidence interval for a three-run case. The cached baseline remains constant and is not used as one of a case's three repetitions.

## Most consequential case mechanisms

**Locale coverage and answer selection.** FE438 best recall is 0.857 versus 0.429; FE6292 is 0.477 versus 0.159; FE6404 is 0.808 versus 0.269/0.115. In FE6404 R3, tool 3 reads the upload-complete component and tool 4 exposes 15 locale paths, yet the final answer omits the owning family and locales. In FE6292, weaker attempts also see the locale directory/files. The plugin needs an evidence-to-answer obligation receipt, not only more searching. Reading full locale bodies is unnecessary: inventory matching key paths and inspect representative values.

**Supporting files becoming changes.** BE6140 starts with the same helper payload and has recall 1.00 throughout, but precision falls from 1.00 to 0.50/0.429. BE5721 has stable true files and variable auth extras. BE5071 has stable aggregate scores but changing extras. Distinguish change owner, evidence-only helper, analogue and proposed new capability; every final path must have a requirement-linked reason. A file being read should not automatically put it in the change set. Historical non-truth paths can still be reasonable engineering choices; evaluate the reason, not merely the mismatch.

**Traversal breadth and byte volume.** BE5973 R3 makes fewer requests than R2 while returning more bytes and costing more. FE5948 weaker attempts return 110–130 KB versus 89 KB in the best attempt. FE5164 plan R2 doubles cost and wall time, peaks at 102,308 tokens and has the same file quality as R1. Single-turn bulk reads should reduce independent I/O waves, but a large batch of irrelevant/full files can make every later request more expensive. Use dependency spans and an overall source-output budget rather than only a per-call cap.

**First divergence versus first loss.** Raw tool signatures frequently differ at the first tool because commands, filters, cwd strategy and descriptions change. FE438 R1/R2 share the first payload and diverge at tool 2; BE6140 has identical initial source output before final scope changes. A lexical difference is not a causal explanation. Each case preserves the first differing request, subsequent result sizes/path mentions, missing final files and resource changes; the manual diagnosis says where a semantic loss is actually supported. Hidden reasoning and hypothetical alternate tool results are not reconstructed.

**Deterministic terminal failures.** All newer task attempts fail before editing, independent of model prose. They then suffer generated-report Stop mismatches and wrong-root recovery. Walk plans are explicitly accepted with failed checks and zero measured AC coverage; this follows the eval Accept policy but should not appear as verified validity. Reviews use replay recordings, not live independent reviewer runs. Improve these infrastructure outcomes before interpreting cheap skill runs as plugin gains.

## Direction: constrain decisions, retain compact state, measure coverage

1. **Repair measurement first.** Use agent trace cost for agent gates; keep judge and total explicit. Add completed/blocked/accepted-with-failed-check/replayed-review columns. Record fixture checks, contract/build hashes, case input hashes and exact artifact provenance. Keep the existing cached bare reference; no new bare runs are needed for this drift audit.
2. **Deliver a small execution state.** Keep skill, step, cwd/root, done/next command and outstanding obligations. Prefer standard readable key/value or JSON-shaped fields with one short legend. Do not invent a symbolic language that requires model interpretation. The existing notation experiment is not a controlled proof of improvement, and the largest within-case drift remains after an identical contract. Keep useful explicit route state; drop unnecessary symbolic compression.
3. **Make discovery families deterministic where grounded.** Extract UI key/owner/consumer families, API handler/schema/DTO dependencies and cross-scoring propagation obligations. Deliver a bounded inventory with a low-confidence fallback for empty/bad maps. A map is a hypothesis; requiring all map leads to be read can amplify ranking errors. Implement ecosystem-specific family logic in an adapter/profile so the engine remains language-agnostic.
4. **Batch required spans, bound total consumption.** Collect independently known files into one call/wave, print canonical operands, allocate relevance-weighted spans and track continuations. A 12 KB default is an experiment, not yet an established fix. Lowering a global cap can create extra continuation turns; first remove useless catalogues/duplicate full bodies and report cumulative served bytes.
5. **Persist evidence to the final decision.** A compact receipt should contain obligation, evidence path/span, role, status and reason to include/exclude. Translation family membership needs to survive after source reading. Completion should check unresolved obligations and final inventory consistency, without inserting truth-oracle paths or pretending a syntactic coverage check verifies semantics.
6. **Fix terminal/gate UX.** Every blocked exit supplies its generated report and an absolute/canonical recovery path. Accept all task/plan decisions permitted by the eval policy; skip optional post-task review. Accepting failed validation must retain failures in the outcome. Eliminate pointless view/server retries and malformed-span/cwd recovery.
7. **Demonstrate the joint target.** Evaluate the same case/config over repeated plugin-only runs after free replay/map/anchor checks. Keep quality floors and resource bounds separate and report joint feasibility and exact path-set stability. Prioritize FE6404/6292/438/5948, BE6140, FE5164 plan, and no-check task exits. Change one mechanism at a time; three new samples can confirm a direction, but cannot certify a future worst-case ±10% guarantee.

## Proposed compact protocol and verification

A standard schema can make the work explicit without a new language. The route can deliver `state={skill,step,root,done,next,openObligations}`; search produces `candidates=[{path,role,reason,confidence}]`; read produces `served=[{path,from,to,truncated,next}]`; final inventory is `changes=[{path,obligation,evidence,status}]`. The model still interprets requirements; the engine can validate canonical paths, duplicates, missing continuations and missing references. Semantic certainty must remain explicit.

For each candidate patch, compare to the best witnessed values in the case grid: all repeated quality values meet their floors, all resource values meet their ceilings, and no blocked/partial outcome is counted as success. Track translation/consumer obligations, answered gates, malformed operands, cumulative result bytes, true evidence omitted from final output, speculative paths, and exact file-set distance. Where maxima conflict (FE6141), require a new observed joint witness. Where all scores are low (FE5164/6406), preserving low variance is insufficient: improve absolute behavioural quality too.

## Additional measurement and map findings

The main 58 attempts have zero AskUserQuestion calls and zero default-taken ledger entries; four cost-capped attempts skip paid graders. Gate Accept policy is represented by explicit preanswers in the skill walk, not by a simulated response to every future unknown gate. Recorded gate/preanswer events are included in each engine timeline.

The helper counter in run-report.mjs uses a command-text regex and misses shell-variable invocations. FE6406 R3 invokes the CLI through `node "$N" read`: the tool classifier reports zero helper calls while the engine records one successful reader receipt with five served spans and 17,071 bytes. Every case now reports both regex-recognized calls and authoritative engine reader receipts/served bytes/truncations. Reading operands and path mentions remain proxies; neither proves full content was returned. The JSON call-level `usd` fields are historical price-derived estimates from the analysis helper; terminal trace cost, not their sum, is the billing reference.

The shared map problem has a specific configuration source. In FE6404 the map records a null search profile and 439/263 matched files filtered outside projects[].shortlist, which defaults to source extensions and excludes tests/styles/markup/data. FE6292 records 513/262 filtered matches. locate.ts:185–190 defines that default. FE6404 consequently delivers mostly dialog/upload-orchestration leads, with only two truth hits and no complete upload-complete/locale family. A compact family inventory for an established owner/key can include relevant markup/data without globally removing ranking bounds. The exact map limitations, terms, profile, decisions and delivered paths are printed in every attempt timeline.

All six walk plan drafts are intentionally absent under their draft filenames after promotion. Artifact validation follows the promoted replacement and checks matching draft/promotion ledger content hashes against exported bytes. Those expected renames are not artifact loss. The artifact score remains distinct from the plan checker failures.
