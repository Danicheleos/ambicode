Change:
1. `--runs N` (default 1) records each case N times. `--keep-runs <dir>` writes every run, not only the last: `<dir>/<case>/run-<k>.json` = `{case, snapshotId, run, recording, findings, usage, costUsd, wallMs}`. The recording is the exact object that goes to `benchmarks/reviewer-recordings.json`, so the file holds NDA output: `<dir>` is refused unless a path segment is `scratch` (gitignored, 06 §2), and it is created if missing.
2. Without `--keep-runs` and with `--runs 1` the behaviour is byte-identical to today and no new file is written. With `--runs N` the recordings file gets, per case, the recording of the highest run index that succeeded (deterministic, independent of completion order).
3. `--keep-runs` also writes `<dir>/summary.json` and `<dir>/usage.json`. summary: per case `{k, counts (all findings, per run), mediumPlusCounts (risk in medium or high, per run), stability}`; stability is exactly the 01 §3 definition (key = `location.newPath ?? location.oldPath`; only findings with risk medium or high; stability = keys present in at least 2 runs / distinct keys over all runs; `null` when no run has a medium-and-above finding). The md5 of the reviewer system prompt and the `policies/` tree hash go into summary only if the worker can compute them from tracked files with no new dependency; otherwise the fields are absent and the handoff says so. usage: per case per run `{turns, apiDurationMs, outputTokens, costUsd}` from `review.reviewer.usage`, each null when the envelope lacked it, never 0.
4. The stability function and the summary builder are exported pure functions with unit tests. One failed run does not drop the other runs of a case; a case with no successful run is listed as refused, as today.
