### 1. Decision 0-V: the Claude Code version gate (decided: option (a) — build it)

**Decided by the user on 2026-10-04: option (a).** Implement (a) as specified below with its tests;
the report records the decision as taken, not as open. Options (b) and (c) stay in this section
only so the reader sees what was weighed.

`withBaseline` refuses the cached baseline whenever `results.claudeVersion !== baseline.claudeVersion`.
The baseline is 2.1.287; today's binary is 2.1.288; by step 3 it will be newer still. D19 forbids a
new baseline. The gate's refusal exists for a reason (`evals-core/README.md`: the no-plugin arm
"depends on the model, the Claude Code version and the prompt"). The options that were weighed:

- **(a)** Add `--accept-baseline-version <ver>` to `evals:gate` and `evals:score`: the gate accepts
  a baseline whose `claudeVersion` equals the given value, prints `GAP  claude-version: baseline
  2.1.287, run <ver>; accepted by flag` as an **unmeasured gap** (not a pass), and the result file
  records it under `baseline.acceptedVersionMismatch`. Cost $0. Weakens the gate explicitly and visibly.
- **(b)** Pin the eval binary to 2.1.287 for the decide run (a second Claude Code install used only
  by `evals-bench.mjs run`). Cost: whatever an older install costs in time; feasibility unknown —
  check `claude --help` / the install docs for a version pin and report what you find, do not install.
- **(c)** Run a new two-arm baseline (≈ $28–30). Ruled out by D19; listed so the user sees the price.

Why (a) was chosen: D19's intent is "do not spend on a baseline", and (a) keeps the refusal visible
as a GAP in every gate output instead of hiding it. What to build: a harness change with its tests —
a gate run against a mismatched baseline **without** the flag still refuses with the existing
message; **with** `--accept-baseline-version 2.1.287` it accepts, prints the GAP line, and the
result file carries `baseline.acceptedVersionMismatch: {baseline: '2.1.287', run: '<ver>'}`; the
flag never accepts a model, prompt, case or arm mismatch (one test per refusal kept). The flag's
value must equal the baseline's `claudeVersion` exactly; any other value → the refusal unchanged
(so a stale flag cannot silently accept a different baseline). `evals:decide`'s documented command
line (33 §1) gains the flag; the `measurements-*/README.md` provenance template records it.

### 3. Per-arm prompts without a new baseline (#46, #101, D19)

**Goal.** The plugin arm runs a typed `/ambicode:investigate … --headless` prompt; the naked arm's
`prompt.md` stays byte-identical to today's generator output; `evals:gate --baseline <2026-10-02>`
accepts a plugin-arm run (subject to §1) and still refuses a changed naked prompt.

**3.1 Settle the mechanism before writing code.** Find out whether the `claude plugin eval` case
format (schema 1.1) lets `case.yaml` name the prompt file (a field such as `prompt`, `prompt_file`,
`prompt_path`). Sources, in order: the documentation at code.claude.com/docs/en/plugin-evals (fetch
it); `claude plugin eval --help`; a dry `claude plugin eval` on a **synthetic** case under a temp
directory with a wrong field to see whether the schema rejects unknown keys (no model call is made
when the scaffold fails or `--max-cost-usd 0` is given — verify that claim before relying on it,
and report what the command did). Record the finding with its source in the report. Then:

- **Mechanism A (a prompt-file field exists):** `select` writes `prompt.md` (naked, unchanged) and
  `prompt.with.md`; `run --prompt with` rewrites each case's `case.yaml` to name `prompt.with.md`
  before spawning and restores it in a `finally`; `run --prompt naked` (default) touches nothing.
- **Mechanism B (no such field):** `select` writes `prompt.md` (naked, unchanged) and
  `prompt.with.md`; `run --prompt with` writes `prompt.with.md`'s content into `prompt.md`, drops a
  `.prompt-swapped` marker beside it, spawns, and in a `finally` restores `prompt.md` from
  `prompt.naked.md` (written by `select` as a byte copy) and removes the marker. `select` refuses to
  run while a marker exists unless `--forced` (which regenerates everything anyway). `run` refuses
  `--prompt with` together with `--ablation with-without` or `--ablation without`: the naked arm must
  never see the typed prompt.

Implement A if it exists, else B. Do not invent a third mechanism (a copied eval directory breaks
the scaffold's relative `benchmarks` path and the no-peek graders; see `evals-core/README.md`
"Trying a variant of a skill").

**3.2 The with-prompt text.** `prompt.with.md` is `prompt.md` with one change: the first line of the
body becomes the typed command, and the rest of the body is unchanged.

```
/ambicode:investigate --headless In the repository at `repo/`, the ticket below is about to be implemented.

<ticket>
…unchanged…
</ticket>

Which files would that change have to touch? … (unchanged to the end)
```

Flags come first so `route start` (step 3) parses them before the free text; `--headless` is the
only flag (D17: no `--requirement`, so no fetch step; 33 §2). The front matter is unchanged
(`allowed_tools` keeps `Skill`; `max_turns`, `timeout_seconds` as today). Review cases get the same
treatment with `/ambicode:review --headless` only when step 8 asks for it; in this step **only
localize cases** get a `prompt.with.md`. Do not change `reviewPromptFile`.

**3.3 Recording.** After the child exits, `run` post-processes the result JSON it named with
`--json`: for every case whose served prompt was `prompt.with.md`, set
`pluginPromptMarkdown := promptMarkdown` (what `claude plugin eval` recorded) and
`promptMarkdown := trim(bodyAfterFrontMatter(prompt.md))` (the naked text, computed from the case
directory at run time, **not** copied from the baseline). Add `suite.servedPrompt: 'with' | 'naked'`.
`withBaseline` is **not** changed (it keeps comparing `promptMarkdown`). `eval-gate` prints one
`info` line: `plugin arm served prompt.with.md (recorded as pluginPromptMarkdown)` when present.
The walk writer (`writeWalk`) prints the served prompt file in its header.

**3.4 Delete the forced-prompt twins** (41 "Deleted": "the forced-prompt eval twins"): `select
--forced` no longer writes `*-forced` review cases; `reviewPromptFile`'s `forced` branch and the
`review-forced` kind in `score` go; tests that assert the twins are rewritten to assert their

**3.5 Tests** (in `evals-bench.test.mjs`, synthetic data only):
