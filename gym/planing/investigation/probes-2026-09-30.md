# Platform probes, 2026-09-30

Iteration 0 of [skill-gap-plan.md](skill-gap-plan.md) depends on these facts.
Each was measured with `claude -p --model claude-haiku-4-5-20251001` in a
scratch directory, or timed locally. The whole set of probes cost under $0.10.

## 1. How much Bash output the model sees

```
bytes printed   what reached the model
20,000          20,000 (whole)
30,000          30,000 (whole)
30,500          2,346  (<persisted-output> preview + path to a saved file)
31,000–97,700   2,346  (same)
```

- Output **over 30,000 characters** is not truncated. It is saved to a
  file, and the model sees a preview of about 2 KB plus the path.
- What AMBICODE prints today, on the benchmark repositories:
  - `prepare --activity investigate --json`: **6,523–6,765 bytes** (BE and FE,
    with or without `--term`).
  - `review` with the replayed reviewer: **5,023 bytes** of stdout.

  Both are far below the limit. The `head -c 6000` the agent added in 28 of
  31 Opus calls was a habit, not something the size forced. It cut only the
  end of `policy` and `provenance`, never `navigation`, which comes first.
- `review.maxContextBytes` (512 KiB) is the only thing that allows a larger
  payload. A payload above 30,000 characters would reach the agent as a
  2 KB preview.

## 2. Hook latency

Each figure is the mean of 20 calls, run locally.

```
bare node, empty script                29.3 ms
standalone hook script (stdin → {})    38.4 ms
ambicode hook, UserPromptSubmit        87.7–99.5 ms
ambicode hook, PostToolUse(Edit)       143.4 ms
```

- The 259 KB bundle costs about 50–60 ms more than a standalone script.
- A `PreToolUse` guard built on the bundle would add about 90–140 ms to
  every matched call. A standalone guard meets the < 50 ms target.
- The existing `PostToolUse(Edit|Write)` hook costs about 143 ms per edit,
  and by default emits nothing (F2).

## 3. What a hook on the `Skill` tool receives

```
PreToolUse   {"tool_name":"Skill","tool_input":{"skill":"echo-probe","args":"hello-world"}}
PostToolUse  {"tool_name":"Skill","tool_input":{…same…},"tool_response":"{\"success\":true,\"commandName\":\"echo-probe\"}"}
additionalContext returned by the PostToolUse hook → reached the model (it quoted "INJECTED-BY-POST-HOOK")
```

This means a `PostToolUse` hook on `Skill` can run `prepare` itself, from the
skill name and args, and hand the result to the model. That is route 1 for
Iteration 4, and it works.

## 4. Command injection in the skill body (route 2 for Iteration 4)

````
SKILL.md body:   !`echo "INJECTED[$ARGUMENTS]" ; pwd`
args "alpha beta"               → INJECTED[alpha beta]; cwd = the session directory
args "x$(echo SUBSHELL-RAN)y"   → INJECTED[xSUBSHELL-RANy]
````

**Rejected.** `$ARGUMENTS` is substituted into the shell text before it is
evaluated, so a command substitution in the args runs. The model writes skill
args, often from ticket text, which is untrusted. Route 2 is a
command-injection hole. No current AMBICODE skill uses `!`-injection (`grep`
over `skills/` and `prompts/`).

**Both routes run in the session's directory.** The benchmark cases put the
repository in `repo/` and tell the agent to `cd repo`. A hook or injection
that runs `prepare` there would get `not-a-repository`. Iteration 4 must
either scaffold the repository as the session directory or have the hook
find the repository beneath it.

## 5. Eval cost levers: model, effort, thinking, single arm

Probed after campaign R1 used up a weekly limit (about $221 API-equivalent in
13.5 h: $56 for the lead, $165 for the evals it started).

**Effort and thinking cannot be switched off from the harness.** Eval
children are isolated. The user's `settings.json` `effortLevel` never reaches
them, and `claude plugin eval` has no effort flag. A one-question
`claude -p` probe on Sonnet (`scratchpad/probe/probe.mjs`) gave:

```
variant                        thinking blocks  output tok  $
default                        1                777         0.078
MAX_THINKING_TOKENS=0          2                745         0.178
CLAUDE_CODE_EFFORT_LEVEL=low   1                449         0.073
--effort low (the real flag)   1                593         0.074
```

`MAX_THINKING_TOKENS=0` does not stop thinking. At n=1 neither the env var
nor the real flag separates from the default. Thinking was 19.6k of 101.8k
output tokens in the 09-30 Sonnet run, about 4.5% of its cost, so a
reliable probe is not worth building. Effort is dropped as a lever.

**Haiku is not cheaper per run.** On one case per kind, Haiku 4.5 is set
against the Sonnet 5.5 runs of 09-29 and 09-30:

```
case                 arm      Haiku $  turns   Sonnet $ (n)          turns
be-vs-5546 localize  with     0.278    38      0.151–0.182 (5)       9–12
                     without  0.225    30      0.111–0.151 (4)       6–7
be-vs-5075 review    with     0.112    15      0.172–0.202 (6)       8–12
```

- On localize, Haiku takes 3–4× the turns, which cancels its lower price.
- On review it costs 0.6× Sonnet's.
- Its behaviour differs from Sonnet's. Haiku fired `ambicode:review` and ran
  the helper unforced; Sonnet did that 0 times in 24 runs. On localize,
  Haiku fired no skill.
- So a Haiku run does not predict a Sonnet run, and it saves little money.
  What saves money is fewer runs.

**`--ablation none` gives `arms: { with: [...] }`**, with `suite.ablation: "none"`.
There is no without-only mode. A cached baseline is therefore the `without`
arm of an ordinary with-without run.

Results: `evals/evals-core/results/eval-2026-09-30T10-35-52-553Z.json` (Haiku,
both arms) and `eval-2026-09-30T10-37-58-313Z.json` (Haiku, single arm). The
probes cost $0.61 in eval runs plus $0.40 in `claude -p`.

## 6. Not probed

- **Whether `PostToolUse` on `AskUserQuestion` carries the chosen answer.**
  `claude -p` cannot answer an interactive question. It needs one interactive
  session with this settings file (replace `<dir>`):

  ```json
  {"hooks":{"PostToolUse":[{"matcher":"AskUserQuestion|ExitPlanMode","hooks":[{"type":"command","command":"cat >> <dir>/ask-events.jsonl; echo >> <dir>/ask-events.jsonl; echo '{}'"}]}]}}
  ```

  Start `claude --settings <that file>`, ask it to put any two-option
  question to you, answer it, and read `ask-events.jsonl`. Iteration 5's plan
  guard depends on the answer. If the answer does not arrive, the fallback is
  `$A accept`.
- **Where the `xcrun`/`xcodebuild` lines in the eval's review output come
  from.** Run locally, `review` wrote nothing to stderr. The lines appear
  only inside the eval sandbox, where writes to `/var/folders` are denied.
  The source process is unverified.
